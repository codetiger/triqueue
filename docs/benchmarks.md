# Benchmarks

Completed measurements for the Tri-Queue core. Every table below is generated by a script in this repository, and the linked file holds the full data. This page only summarizes it.

**Scope.** These are **utilization** results: useful MACs ÷ (peak MACs per cycle × cycles). Area, power and clock frequency have not been measured yet, so nothing here is a performance-per-watt or performance-per-area claim. Shapes come from `bench/workloads/gemm.csv`.

## 1. Cycle model, T = 8 (64 int8 MACs per cycle)

Source: `model/results.md` (`model/bench.py`). Memory latency 2, FIFO depth 8, separate write port. Every run is bit-exact against numpy.

| M×N×K | Cycles | Utilization | Limited by |
| --- | --- | --- | --- |
| 16×16×16 | 101 | 63.4% | Fixed 34-cycle start/end overhead |
| 32×32×32 | 546 | 93.8% | Fixed overhead |
| 64×64×64 | 4,130 | 99.2% | Nothing significant |
| 256×256×256 | 262,178 | 100.0% | Nothing significant |
| 60×60×60 | 3,859 | 87.5% | Edge tiles, K padded to 64 |
| 65×65×65 | 5,524 | 77.7% | 1-row/1-col remainder tiles, K padded to 72 |
| 1×512×512 | 24,593 | 16.7% | Matrix-vector: the read port caps it at 25% |

Further tables in the source file: shared read/write port (79.8% at 64³), drain hiding versus K, MAC command queue depth, and FIFO depth versus SRAM latency.

## 2. RTL, T = 8

Source: `verif/` (`make rtl-test`). The SystemVerilog core gives the same cycle count as the model for every one of 840 regression cases in 9 configurations (T = 4, 8, 16, 32; shared port; minimal queues; both accumulator forms; random memory back-pressure of 10–80%), including **4,130 cycles for 64³**. Results are bit-exact, and every memory transaction and MAC start happens on the same cycle as in the model.

## 4. Apple AMX reference (M2 Pro, measured)

Source: `bench/reference/amx/results.md` and `ablation.md`. AMX is fp32 at 256 MACs per cycle per unit, and the Tri-Queue figures are from the int8 cycle model at 64 MACs per cycle. Only utilization is compared, each against its own engine's measured peak.

| M×N×K | Tri-Queue (model) | AMX hand kernel | Accelerate sgemm, 1 thread |
| --- | --- | --- | --- |
| 32×32×32 | 93.8% | 31.5% | 7.8% |
| 64×64×64 | 99.2% | 78.3% | 33.5% |
| 256×256×256 | 100.0% | 91.0% | 74.3% |
| 512×512×512 | – | 93.1% | 86.9% |

**Accumulator double-banking (64×64×K), measured independently of precision:**

| K | AMX (1 accumulator, measured) | Tri-Queue, 1 bank | Tri-Queue, 2 banks |
| --- | --- | --- | --- |
| 8 | 16.8% | 30.5% | 46.0% |
| 16 | 39.9% | 46.7% | 91.3% |
| 32 | 62.2% | 63.7% | 98.4% |
| 128 | 81.5% | 87.5% | 99.6% |
| 1024 | 90.9% | 98.2% | 99.9% |

The second bank removes the per-tile drain stall that a production outer-product engine measurably pays. Spec §7.2 explains why this advantage depends on 1-cycle integer accumulation and doesn't carry over to floating point.
