# Benchmarks

Completed measurements for the Tri-Queue core. The tables are generated by scripts in this repository (`model/results.md`, `model/dse.md`, `flow/results.md`, `bench/reference/amx/*.md`); this page is a hand-maintained summary. When a generated file changes, update the matching summary here. The linked file holds the full data.

**Scope.** Sections 1–4 are **utilization** results: useful MACs ÷ (peak MACs per cycle × cycles). Section 5 has area, clock frequency and energy after place and route at T = 8 and T = 16. The operand SRAM is outside `tq_top`, so engine-only figures are shown alongside a separate engine + SRAM line on sky130hd. Section 6 covers the Chipyard Rocket SoC run. Shapes come from `bench/workloads/gemm.csv`.

## 1. Cycle model, T = 8 (64 int8 MACs per cycle)

Source: `model/results.md` (`model/bench.py`). Memory latency 2, FIFO depth 8, separate write port. Every run is bit-exact against numpy.

| M×N×K | Cycles | Utilization | Limited by |
| --- | --- | --- | --- |
| 16×16×16 | 101 | 63.4% | Fixed 34-cycle start/end overhead (+ 3 drain-wait cycles at K = 16) |
| 32×32×32 | 546 | 93.8% | Fixed overhead |
| 64×64×64 | 4,130 | 99.2% | Nothing significant |
| 256×256×256 | 262,178 | 100.0% | Nothing significant |
| 60×60×60 | 3,859 | 87.5% | Edge tiles, K padded to 64 |
| 65×65×65 | 5,524 | 77.7% | 1-row/1-col remainder tiles, K padded to 72 |
| 1×512×512 | 24,593 | 16.7% | Matrix-vector: the read port caps it at 25% |

Further tables in the source file: shared read/write port (79.8% at 64³), drain hiding versus K, MAC command queue depth, and FIFO depth versus SRAM latency.

**Int8 output** (`MODE[2]`, shift-only). The drain writes one tile row per write instead of one port word of int32, so an int8 tile takes 8 writes instead of 16 at T = 8. On a separate port this takes 64³ from 99.2% to 99.4% and lifts 64×64×8 from 46.0% to 85.2% and 64×64×16 from 91.3% to 97.5%; on a shared port it lifts 64³ from 79.8% to 88.7%, 64×64×8 from 33.1% to 49.5% and 64×64×16 from 49.7% to 66.2% (`model/dse.md` §8). This is shift-only requantization, not a per-tensor scale.

**Int8 layer path** (`model/dse.md` §9, tag `layerpath`). The pointwise layer 2304×16×8 runs at 46.9% with int32 C and 88.5% with int8 C: C bytes fall 4× (147,456 → 36,864) but write transactions only 2× (9,216 → 4,608), so SRAM bytes per MAC halve (0.75 → 0.375). Batched decode (4×512×512) reaches 99.1% with a 4 KiB A-panel buffer and 8×512×512 reaches 99.9% without one; a batch-1 GEMV (1×256×K) stays at the 16.6–16.7% port-limited value until the buffer holds the whole panel — 24.6% with 4 KiB for K ≤ 1024, and 16 KiB is needed at K = 4096. The model does not charge for the host packing pass.

**Chaining output layout** (`model/dse.md` §10, model study only). Writing C in the next layer's A-panel order is bit-exact with the host packer and halves int8 write transactions again (4 words per tile at T = 8, against 8 for int8 rows and 16 for int32), removing activation repacking between layers. The default row-serial drain needs T−1 cycles before its first word, which is exposed at small K: 64×64×8 runs at 64.6% against 85.2% for int8 rows, and 2304×16×8 at 66.4% against 88.5%. A drain that snapshots the bank reaches 95.7% and 99.5%; at Kp ≥ 16 the layout is free either way.

**Epilogue delivery** (`model/dse.md` §11). Per-tensor scale and a bias adder in the drain lane cost no cycles; a per-column bias plus 16-bit scale delivered as a per-tile stream is 3 port words per tile (+37% of the operand traffic at Kp = 8), so per-column metadata wants a table. Bias as an extra k step costs a whole 8-step padding panel when K is a multiple of 8: 64×64×8 85.2% → 54.9%, 2304×16×8 88.5% → 56.1%; it is free when K mod 8 ≠ 0.

## 2. RTL, T = 8

Source: `verif/` (`make rtl-test`). The SystemVerilog core gives the same cycle count as the model for every one of **1,755 regression cases in 27 configurations** (T = 4, 8, 16, 32; shared port; minimal and reference queues; both accumulator forms; panel buffer; single-beat and burst AXI; CV-X-IF; and random memory back-pressure of 10–80%), including **4,130 cycles for 64³**. Results are bit-exact, and every memory transaction and MAC start happens on the same cycle as in the model. See [`docs/verification.md`](verification.md) for the matrix and the known coverage gaps.

## 5. Place and route, T = 8 and T = 16

Source: `flow/results.md` (`flow/results.py`, from runs of `flow/ppa.py` and `flow/power.py`). OpenROAD-flow-scripts `d0e5b3c13`, typical corner, post-route STA and extracted parasitics. Power comes from simulating each workload in Verilator (checked against the model) with uniform random int8 operands, which switch more than real data. Reference configuration: plain-adder accumulator, clock gating on, operand FIFOs of depth 4 and a 3-entry MAC command queue (enough for an SRAM with up to 3 cycles of read latency, `L ≤ 3` / model `mem_latency ≤ 4`, with no cycle lost). Engine only unless stated.

| | sky130hd, T = 8 (100 MHz, 55% util) | ASAP7, T = 8 (1 GHz, 70% util) | ASAP7, T = 16 (741 MHz, 70% util) |
| --- | --- | --- | --- |
| Cell area / core area | 0.677 mm² / 1.060 mm² (180.4 kGE) | 10,062 µm² / 13,385 µm² (172.5 kGE) | 31,102 µm² / 42,462 µm² (533.3 kGE) |
| Post-route stdcell density | 64.0% (100.0% row fill) | 75.2% (100.0% row fill) | 73.2% |
| Flip-flops | 8,571 (134 per MAC) | 8,571 (134 per MAC) | 25,553 (100 per MAC) |
| Fmax (post-route, all setup checks) | 99.2 MHz (-85 ps slack) | 1,001.9 MHz (+2 ps slack) | 747.4 MHz (closes 741 MHz, +12 ps) |
| Peak MACs/cycle per kGE | 0.355 | 0.371 | 0.480 |
| Energy per MAC, 64×64×64 (96.8% / 87.2% util) | 16.0 pJ (0.125 TOPS/W) | 0.63 pJ (3.17 TOPS/W) | 0.62 pJ (3.25 TOPS/W) |
| Energy per MAC, ResNet-8 conv 256×32×288 (99.6% / 98.4%) | 15.5 pJ (0.129 TOPS/W) | 0.61 pJ (3.28 TOPS/W) | 0.58 pJ (3.45 TOPS/W) |
| Energy per MAC, MobileNetV1 pointwise 2304×16×8 (46.5% / 23.6%) | 23.5 pJ (0.085 TOPS/W) | 0.97 pJ (2.06 TOPS/W) | 1.11 pJ (1.80 TOPS/W) |
| Energy per MAC, FC-autoencoder GEMV 1×128×640 (16.4% / 8.1%) | 43.7 pJ (0.046 TOPS/W) | 1.99 pJ (1.00 TOPS/W) | 3.11 pJ (0.64 TOPS/W) |
| Geometric mean of the four | 22.5 pJ (0.089 TOPS/W) | 0.93 pJ (2.15 TOPS/W) | 1.05 pJ (1.90 TOPS/W) |
| ResNet-8 conv with ReLU-like operands (synthetic, half-zero activations) | 13.1 pJ (0.152 TOPS/W) | 0.52 pJ (3.85 TOPS/W) | 0.48 pJ (4.14 TOPS/W) |
| Engine + operand SRAM, geometric mean (OpenRAM macro, sky130 only) | 28.9 pJ (0.069 TOPS/W) | – | – |

- **Geometric means** cover four workloads: the three dense and pointwise shapes and the port-bound GEMV, which is what pulls them up. Over the three of the earlier records alone they are 18.0 pJ, 0.72 pJ and 0.74 pJ (the earlier records: 19.1, 0.79 and 0.82 pJ). The simulated window includes about 100 setup cycles (reset, program load, the regression's register-port checks, counter reads), which only overstates energy per MAC: 2.4% of the T = 8 `gemm64` window, about 8% at T = 16.
- **Idle-logic power:** the drain's output-mode isolation, the lazy accumulator clear and the two-level program/`CFG` clock gates (spec §10.8) lower energy per MAC by 4.9–7.2% on sky130hd and 8.2–12.8% on ASAP7 (T = 8 and T = 16) against the earlier records of the same workloads, with no cycle count change. The multiplier inputs already change only when a beat consumes operands, so operand isolation has nothing to remove there.
- **Clock gating** (`CLK_GATE = 0` for comparison) cuts power by 25–54%, cell area by 10.3% and energy per MAC by 38.2% (sky130hd; ASAP7: 26–49%, 9.0% and 35.8%), at essentially the same clock. The relative power saving is larger at lower utilization because the gated clock trees and registers stop switching. What remains is mostly the multiplier array's switching, which follows the operand data.
- **Accumulator form:** against carry-save, the plain adder uses 20.9% less cell area, has 31.6% fewer flip-flops and uses 21.9% less energy per MAC on sky130hd (ASAP7: 16.9%, 31.6%, 19.6%), at a slightly higher clock (spec §10.2).
- **Fmax** counts every setup check, clock-gating and I/O checks included: 1 ÷ (period − worst slack). OpenROAD's register-to-register figure, which skips the clock-gating checks, is higher (102.6 MHz, 1,053 MHz and 843 MHz) and is kept in the records as `fmax_reg2reg_hz`.
- **SRAM line:** each workload's reads and writes times the access energy of ORFS's OpenRAM macro `sky130_sram_1rw1r_128x256_8` (179 pJ per access from its liberty, which charges every clock edge the same), plus leakage; it adds 3.0–8.4 pJ per MAC to the GEMMs and 16.9 pJ to the GEMV, which has the least operand reuse. ASAP7 has only placeholder SRAM models, so it has no SRAM line.
- **Layout signature:** each layout carries "codetiger.in" in physical-only cells at the bottom of the core (`flow/logo.tcl`, `NOTICE`); the netlist is unchanged and the cells are left out of the cell area and count.

## 6. SoC integration (Chipyard Rocket)

Source: `bench/soc/chipyard/README.md`. A one-core Rocket SoC (Chipyard 1.15.0) with `tq_top_axi` attached to the periphery and front buses, running a 64×64×64 int8 GEMM in Verilator through `sw/tq.c`.

It passes with 0 mismatches and the same 4,096 beats, 4,096 reads and 1,024 writes as the cycle model (v1.0.2 RTL, 2026-11-20):

| Memory master | Cycles | Utilization |
| --- | --- | --- |
| `BURST_BEATS = 4` (the shim's setting: one 64-byte line per AR) | **17,187** | **23.8%** |
| `BURST_BEATS = 1` (one 16-byte word per AR) | 38,686 | 10.5% |
| Fixed-latency SRAM, 2 cycles (cycle model and RTL) | 4,130 | 99.2% |

The 8-word operand FIFOs are meant for tightly coupled SRAM and do not hide the latency of the TileLink-to-AXI bridge, L2 cache and DRAM. Read bursts take one round trip per line instead of per word and cut the cycles 2.25×. This is a memory-latency result, not a core limit: the supported v1 integration is a low-latency SRAM or TCM. A deeper FIFO and the optional panel buffer are the other levers for a cached-memory SoC and have not been measured in the SoC (`docs/integration.md`). The single-beat run matches the pre-v1 result (38,295 cycles, 2026-11-08, `65815f3`).
