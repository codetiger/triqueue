# Tri-Queue: an open matrix coprocessor for RISC-V

An open-source RTL matrix-multiply coprocessor for RISC-V SoCs, in the same class as Apple's AMX, Arm SME and Gemmini. It is designed to drop into a larger chip and to be measured honestly against the alternatives.

**Status:** RTL v0. The SystemVerilog core matches the cycle-level Python model cycle for cycle and is bit-exact against numpy across 643 regression cases. Area, power and clock frequency have not been measured yet.

## Why

Open matrix engines exist, but they are hard to compare: each is evaluated in its own flow, on its own workloads, at its own process node. Most are also tied to one SoC generator. This project aims to provide:

1. **An efficient matrix engine.** It should get close to the utilization of production engines like AMX, with far less state. The current design reaches 99% of peak on 64³ int8 GEMM with about 10 Kbit of operand state and no register file.
2. **Easy integration.** A core that is independent of any interface, with thin adapters for standard SoC buses and RISC-V coprocessor interfaces, plus a C driver.
3. **Fair, reproducible comparison.** The same workloads, the same open PDK and the same synthesis flow for this design and for other open designs, with every number regenerated by a script in the repo.

## Design priorities

In order of importance:

| Priority | Metric |
| --- | --- |
| Performance per watt | Useful int8 ops per joule (TOPS/W) on real workload shapes, not peak |
| Performance per component | Useful MACs/cycle per mm² and per kGE; operand state bits per MAC |
| Design reusability | Parameterized core, standard interfaces, no dependency on a particular SoC generator |
| Overall efficiency | Utilization across a workload suite, including small, edge-tile and GEMV shapes |

Peak throughput is a parameter, set by tile size and port width. It is not a goal in its own right.

## Repository

| Path | Contents |
| --- | --- |
| `docs/benchmarks.md` | Summary of every completed benchmark, with links to the generated results |
| `docs/spec/` | The design spec (`tri_queue_matrix_core_design.md`, including the host and memory interfaces) and the golden-vector / trace format |
| `model/` | Cycle-level Python model: runs the real instruction bytes, bit-exact against numpy. This will be the golden reference for RTL. |
| `rtl/` | SystemVerilog RTL (`tq_top`), parameterized by tile size; see `rtl/README.md` for interfaces |
| `verif/` | cocotb + Verilator regression against the model, SymbiYosys proofs |
| `bench/workloads/` | The shared list of GEMM shapes that every benchmark uses |
| `bench/reference/amx/` | Apple AMX (M2 Pro) measurements used as a real-silicon reference |

Quick start (Python 3.10+; RTL targets need Verilator 5, Yosys and SymbiYosys):

```
git clone https://github.com/codetiger/triqueue.git && cd triqueue
pip install -r requirements.txt
make              # model tests, RTL lint, RTL regression, formal proofs, synthesis check
```
